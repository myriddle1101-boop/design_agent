# 前端技术方案

## 1. 文档定位

- 阶段：P4 前端技术方案。
- 输入：已确认的《内容与信息架构文档》《素材清单》《视觉与动效规范》。
- 输出范围：技术栈、架构、组件、状态、数据、设计 Token、媒体、动效、响应式、可访问性和测试策略。
- 本阶段不包含：项目初始化、依赖安装、网站代码、素材再加工、部署和正式视觉迭代。
- 核心原则：**静态优先、URL可分享、数据驱动、渐进增强、真实内容优先、减少动态可完整降级**。

## 2. 关键技术决策

| 决策 | 结论 | 原因 |
|---|---|---|
| 应用形态 | 静态生成的多页面网站，不做纯客户端单页应用 | 内容稳定、无需登录或实时后端；更利于首屏、SEO、分享、刷新和无脚本访问 |
| 一级Tab | 映射为真实页面路由 | 保证浏览器前进/后退、刷新、深链和当前导航状态可靠 |
| 项目详情 | 独立动态路由在构建期生成静态页面 | 每个项目可分享、可索引；列表与详情职责清晰 |
| 内容来源 | 本地类型化内容集合 | 防止文案、链接和素材散落在组件中；构建时校验必填字段 |
| 交互方式 | 原生HTML/CSS优先，复杂组件局部水合 | 降低脚本体积与运行风险；无JavaScript时核心内容仍存在 |
| 后端 | R0不需要 | 当前没有联系表单、账户、CMS或动态业务数据 |
| 动效 | CSS与浏览器原生能力优先；复杂动效按需引入 | 基础反馈不依赖重型库，复杂效果可以独立关闭和回退 |
| 缺失素材 | 明示占位，不生成仿真内容 | 保持研究真实性和一对一替换能力 |

## 3. 技术栈

### 3.1 推荐栈

| 层 | 选择 | 用途与边界 |
|---|---|---|
| 框架 | Astro，静态输出模式 | 页面路由、构建期生成、SEO元信息、图片处理、静态HTML |
| 语言 | TypeScript 严格模式 | 内容模型、组件属性、路由参数和工具函数校验 |
| 交互岛 | React，仅用于确有复杂状态的组件 | 项目筛选、精选轮播、拖拽图库；不包裹整页 |
| 样式 | CSS Custom Properties + 组件级CSS | Token、主题、响应式、状态和减少动态；不引入完整UI组件库 |
| 内容 | Astro Content Collections + Markdown/结构化数据 | AI项目和设计作品详情；构建期进行字段校验 |
| 图标 | 自建少量SVG或经过许可的单一图标集 | 箭头、外链、复制、下载、播放等功能图标；避免混用多套风格 |
| 单元/组件测试 | Vitest + Testing Library + user-event | 数据工具、过滤逻辑、复制反馈和交互组件 |
| 端到端测试 | Playwright | 路由、Tab、筛选、详情、外链、下载、响应式和键盘流程 |
| 无障碍自动检查 | `@axe-core/playwright` | 检查可自动发现的WCAG A/AA问题；不能替代人工测试 |
| 代码质量 | ESLint、Prettier、Stylelint | TypeScript、Astro/React和CSS一致性 |

### 3.2 为什么选择Astro而不是整站React SPA

- 六个Tab和项目详情本质是内容页面，不需要整站客户端状态。
- Astro可把主要内容输出为静态HTML，只给筛选、轮播、拖拽图库等局部组件加载JavaScript。
- 页面级路由天然支持分享、刷新、浏览器历史、标题和元信息。
- 依然可使用React实现复杂交互，不牺牲后续扩展能力。

### 3.3 依赖控制

- R0开始前根据当时官方兼容矩阵确定并锁定版本，提交锁文件；本方案不预写未经安装验证的版本号。
- 不引入Tailwind或大型组件库：视觉语言高度定制，抽象成本大于收益。
- 不在R0默认引入GSAP、Lottie、Matter.js或Canvas框架。
- 如原生能力无法达到已确认的3D轮播或路径响应，再单独评估GSAP；必须检查包体积、许可、清理机制和减少动态分支。
- 动效参考只能重写为本站实现，不能直接复制受限制示例的完整代码或素材。

## 4. 路由与Tab状态

### 4.1 路由表

| URL | Tab | 页面职责 |
|---|---|---|
| `/` | Home | 身份、代表证据、项目入口与快速联系 |
| `/experience/` | Experience | 教育、实习时间线、职责与结果 |
| `/ai-projects/` | AI Projects | AI项目列表与筛选 |
| `/ai-projects/[slug]/` | AI Projects | AI项目详情 |
| `/portfolio/` | Portfolio | 设计作品列表与筛选 |
| `/portfolio/[slug]/` | Portfolio | 设计作品详情 |
| `/about/` | About | 跨学科能力、兴趣、工具与自述 |
| `/contact/` | Contact | 邮箱、电话、简历与外链 |
| `/404.html` | 无 | 路由不存在或slug无效时的恢复入口 |

建议slug：

- AI：`pathly`、`ai-schengen-assistant`、`smart-clothing-advisor`。
- Portfolio：`seed-the-sun`、`para-gaze`、`cocoon`、`ash-lifecycle`、`stree-plus-scape`、`ouroute`、`other-works`。

### 4.2 一级Tab状态

- 当前Tab由 `pathname` 派生，不单独保存在React状态或本地存储。
- 项目详情页继承父级Tab激活状态：`/ai-projects/*` 激活 AI Projects，`/portfolio/*` 激活 Portfolio。
- 导航采用普通链接和 `aria-current="page"`；没有JavaScript也可导航。
- 桌面显示六项导航；移动端使用可展开菜单，但展开按钮和菜单项都必须可键盘操作。
- 页面切换后主内容获得合理的阅读起点；不强制把焦点移动到装饰元素。
- 使用浏览器历史和页面级滚动恢复；跨Tab深链携带锚点时滚动到对应区块。

### 4.3 深链与查询状态

| 状态 | URL表达 | 是否持久化 | 说明 |
|---|---|---|---|
| AI筛选 | `/ai-projects/?filter=agent` | 是 | 支持分享与刷新；无效值回退到“全部” |
| 作品筛选 | `/portfolio/?filter=service-design` | 是 | 过滤后更新结果数量和空状态 |
| 项目详情 | 路由slug | 是 | 不使用只存在内存的弹窗作为唯一详情入口 |
| 经历定位 | `/experience/#tencent` | 是 | 用稳定ID定位；展开目标经历 |
| 详情图库当前图 | 默认不写URL | 否 | 属于临时浏览状态；刷新回第一张 |
| 经历展开状态 | 默认不持久化 | 否 | 锚点目标例外；其余刷新后回到默认摘要 |
| 移动菜单 | 组件本地状态 | 否 | 路由变化或Escape后关闭 |
| 复制成功 | 组件本地短暂状态 | 否 | 文字反馈至少保留2秒 |

### 4.4 返回与滚动行为

- 从列表进入详情时，在历史中保留列表URL和筛选查询；返回后恢复筛选与合理滚动位置。
- 从首页代表卡进入项目详情，可直接进入详情，不要求先经过列表。
- 页面内锚点目标使用 `scroll-margin-top` 避免被粘性导航遮挡。
- 减少动态模式下不使用平滑滚动；普通模式的平滑滚动仅用于页内短距离导航。

## 5. 信息架构到组件结构

### 5.1 目录职责建议

```text
src/
├─ layouts/           页面壳、SEO、导航与页尾
├─ pages/             八类公开路由与404
├─ components/
│  ├─ global/         Header、TabNav、Footer、SkipLink
│  ├─ ui/             Button、Tag、WindowCard、PlaceholderMedia等
│  ├─ content/        SectionHeader、MetricList、RichContent等
│  ├─ projects/       ProjectCard、ProjectGrid、ProjectDetail等
│  └─ interactive/    FilterBar、Carousel、StackPreview、Gallery等
├─ content/
│  ├─ ai-projects/    AI项目内容条目
│  └─ portfolio/      设计作品内容条目
├─ data/              个人信息、教育、经历、导航、外链
├─ styles/            Token、基础样式、工具类、减少动态
├─ assets/            由构建管线处理的本地图片和SVG
└─ utils/             内容查询、URL、媒体和格式化工具
public/
├─ downloads/         已确认公开的简历PDF
├─ fonts/             仅存放已授权且确需自托管的字体
└─ static/            不需构建处理的固定文件
```

这只是未来代码结构约定，本轮不创建这些目录。

### 5.2 全局组件

| 组件 | 职责 | 主要状态 | 渲染策略 |
|---|---|---|---|
| `SiteLayout` | 文档语言、元信息、Header、main、Footer | 无客户端状态 | 静态 |
| `SkipLink` | 跳到主内容 | focus | 静态 + CSS |
| `SiteHeader` | 品牌、一级导航、移动菜单入口 | 当前路由、菜单开关 | 导航静态；移动菜单少量脚本 |
| `TabNav` | 六个真实页面链接 | 由pathname派生激活项 | 静态 |
| `SiteFooter` | 联系与辅助导航 | 无 | 静态 |
| `PageHeader` | Tab标题、简介、可选CTA | 无 | 静态 |
| `SectionHeader` | 区块标题和说明 | 无 | 静态 |
| `ButtonLink` | 内链、外链、下载、邮件等统一外观 | hover/focus/pressed | 静态 + CSS |
| `WindowCard` | 复古窗口式卡片框架 | 可选激活态 | 静态 |
| `Tag` | 类型、年份、技能和结果标签 | 选中/未选中 | 静态或交互父组件控制 |
| `PlaceholderMedia` | 明示缺失素材与计划用途 | 无 | 静态 |

### 5.3 页面与业务组件

| 页面 | 核心组件 | 交互边界 |
|---|---|---|
| Home | `HeroIdentity`、`EvidenceCardGrid`、`FeaturedProjects`、`DesignPreview`、`QuickContact` | 精选轮播只能增强项目浏览，所有入口在静态状态下可见 |
| Experience | `EducationTimeline`、`ExperienceTimeline`、`ExperienceDisclosure`、`MetricList` | 展开/收起；数据只展示已确认值，不绘制伪趋势图 |
| AI Projects | `ProjectFilter`、`ProjectGrid`、`AIProjectCard` | 查询参数控制筛选；卡片进入独立详情页 |
| AI详情 | `ProjectHero`、`ProjectFacts`、`ProcessSections`、`EvidenceGallery`、`ExternalLinks` | 图库可增强为拖拽；按钮和缩略图始终存在 |
| Portfolio | `PortfolioFilter`、`ProjectGrid`、`StackProjectCard` | hover/focus层叠只作装饰；点击行为保持普通链接 |
| 作品详情 | `ProjectHero`、`NarrativeSection`、`MediaGallery`、`VideoLink`、`Credits` | 按“命题—研究—过程—原型/技术—结果”排序 |
| About | `ProfileIntro`、`CapabilityList`、`InterestGrid`、`ToolList` | 兴趣素材缺失时显示文字或明确占位，不生成作品 |
| Contact | `ContactMethods`、`CopyEmailButton`、`ResumeDownload`、`ExternalLinkList` | 复制失败提供可手选文字；不需要后端表单 |

### 5.4 组件边界原则

- 以内容语义和复用场景拆分，不按每个视觉小块创建组件。
- 可点击卡片不得在外层链接中嵌套按钮；整卡链接与次级CTA要选择一种清晰结构。
- 装饰图层独立于语义DOM，并标记为辅助技术忽略。
- 复杂互动必须有静态DOM基线，水合失败不能导致内容消失。
- 项目卡和项目详情读取同一条内容数据，避免两套文案漂移。

## 6. 内容数据方案

### 6.1 数据分层

| 数据组 | 建议存储 | 原因 |
|---|---|---|
| 站点信息 | 单一站点配置 | 姓名、默认描述、邮箱、电话、简历地址统一来源 |
| 导航 | 导航配置 | 顺序、标签、路径和父级匹配统一管理 |
| 教育/经历 | 类型化数据文件 | 结构固定、条目少、需要按时间排序与锚点定位 |
| AI项目 | 内容集合 | 每个项目有长文、媒体、分类、结果、链接和详情页 |
| 设计作品 | 内容集合 | 每个作品有叙事章节、图组、来源页、团队与外链 |
| 外部链接 | 独立链接清单或项目字段 | 保存来源、公开许可、核验状态和最近核验日期 |
| 媒体 | 媒体清单 | 保存本地路径、alt、比例、来源页、版权/署名与占位状态 |

### 6.2 项目通用字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `slug` | 是 | 稳定URL标识，发布后避免随意修改 |
| `title` | 是 | 真实项目名称 |
| `kind` | 是 | AI项目或设计作品 |
| `summary` | 是 | 卡片和元信息使用的事实摘要 |
| `categories` | 是 | 允许筛选的受控枚举，不使用自由拼写 |
| `period` | 视材料 | 有真实证据才填写；未知时省略，不显示“待补日期”给访客 |
| `role` | 视材料 | 团队项目必须明确；OURoute记录“组长”并保留团队属性 |
| `teamDisclosure` | 团队项目必填 | 说明是团队成果，防止整体成果被误认为个人独立完成 |
| `problem` | 是 | 项目命题或用户问题 |
| `contributions` | 是 | 本人可确认的行动 |
| `outcomes` | 视材料 | 仅保存有来源的结果，带单位、近似标志和证据说明 |
| `sections` | 是 | 详情页叙事区块及顺序 |
| `cover` | 是 | 本地媒体或明确占位 |
| `gallery` | 否 | 媒体ID数组，不在正文重复写文件路径 |
| `links` | 否 | 演示、视频、GitHub、PDF等引用 |
| `sourceNotes` | 是 | PDF页码或来源说明，仅用于内容治理，可选择不公开 |
| `status` | 是 | 已上线、课程项目、作品集项目等真实状态；不推断 |

### 6.3 结果数据结构规则

- 每条量化结果分成：显示值、指标名称、上下文、是否近似、来源说明。
- `约20%` 与 `20%` 不是同一数据；近似信息必须保留。
- 不从多个离散结果生成时间趋势、因果关系或总增长率。
- 团队结果和个人贡献分开字段展示。
- 技能不提供百分比或伪熟练度。

### 6.4 媒体字段规则

每个媒体条目至少记录：

- 唯一ID与文件名；
- 本地路径或外部URL；
- 类型：图片、视频链接、PDF、本地HTML或占位；
- 宽高比；
- alt文本或装饰标记；
- 所属项目和内容区块；
- 来源文件及页码；
- 用途：封面、过程、系统、结果、团队等；
- 权利/署名状态；
- 是否允许公开；
- 是否为占位及替换说明。

### 6.5 已知内容冲突处理

- AI申根签小助手在内容文档和素材清单中出现两个不同网址。数据层必须只保留一个 `primaryUrl`，另一个进入 `alternateUrls`；R0写入内容前重新核验并由用户确认主链接，不能静默选择。
- Smart Clothing Advisor 已由用户确认加入 AI Projects，不能继续显示为“候选”。
- OURoute 已由用户确认加入 Portfolio，角色为组长；页面必须同时保留团队署名或团队项目说明。
- 首页照片已确认裁成方图；媒体数据仍要记录原始来源与裁切焦点。
- 素材清单中历史“待确认”描述不得覆盖后续用户确认，以 `RECORD.md` 的时间顺序和最新确认状态为准。

## 7. 设计Token方案

### 7.1 Token分层

1. **基础Token**：原始颜色、字号、间距、圆角和时长。
2. **语义Token**：背景、文字、边框、强调、焦点、成功、错误等角色。
3. **组件Token**：卡片、按钮、导航、标签和媒体框的局部映射。

组件只能优先使用语义Token；禁止在大量组件中散写颜色和间距常量。

### 7.2 色彩Token

沿用P3值：

| 基础Token | 值 | 语义用途 |
|---|---|---|
| `navy-950` | `#082F5B` | 深色主背景 |
| `navy-800` | `#155486` | 深色次层 |
| `sky-200` | `#BFE4EE` | 浅蓝分区、窗口栏 |
| `paper` | `#FFFDF2` | 默认页面和卡片背景 |
| `green-700` | `#287A3C` | 链接、成功、深绿文字 |
| `green-500` | `#65B83F` | 主绿色块 |
| `lime-300` | `#D6F044` | 选中和荧光标签 |
| `star-400` | `#FFD51F` | 焦点与星点 |
| `orange-400` | `#F48A38` | 小面积分类点缀 |
| `ink` | `#10202B` | 浅底正文和描边 |
| `white` | `#FFFFFF` | 深底文字与路径 |

R0必须使用实际组件做对比度复核；设计值不能替代可访问性测试结果。

### 7.3 尺寸与排版Token

- 间距采用接近4px基准的受控序列：4、8、12、16、24、32、48、64、96、128。
- 圆角建议：小控件10px、标签999px、卡片18px/24px/28px、媒体框24px。
- 边框：1px默认、2px强调；焦点环2–3px，外偏移2px。
- 内容最大宽度1280px；正文窄列建议不超过72个中文字符的视觉宽度。
- 字号使用 `clamp()` 在P3桌面和移动范围内流动，不依赖大量断点突变。
- 字体家族：中文正文为思源黑体/Noto Sans SC回退链；英文数字为Inter回退链；技术标签用等宽回退链。

### 7.4 动效Token

| Token类别 | 建议值 |
|---|---|
| 快速反馈 | 120–220ms |
| 展开/收回 | 240–420ms |
| 卡片切换 | 450–700ms |
| 区块进入 | 500–800ms |
| 弹性强调 | 700–1000ms，仅单个焦点对象 |
| 标准缓动 | 快速ease-out |
| 弹性缓动 | 自定义受控曲线，不能用于减少动态模式 |

减少动态媒体查询应覆盖这些组件Token，而不是在每个组件临时补丁。

### 7.5 层级Token

- 页面内容：`0`。
- 粘性导航：`20`。
- 下拉/移动菜单：`30`。
- 模态媒体查看器（若后续确认）：`40`。
- Toast/复制反馈：`50`。
- 装饰图层使用负层级或内容内部低层级，不得覆盖链接和焦点环。

## 8. 媒体处理方案

### 8.1 素材进入项目的流程

1. 从 `D:\design\_agent\material` 读取已确认素材。
2. 复制到项目受版本控制的素材目录；不让生产构建依赖D盘绝对路径。
3. 为每项素材登记媒体ID、来源、用途、alt、裁切和公开状态。
4. 生成适合网页的派生格式；保留原始源文件，不覆盖。
5. 在固定视口检查裁切、清晰度和加载行为。

### 8.2 图片

- 可处理图片放入构建资源目录，由图片管线生成多尺寸 `srcset`。
- 输出优先AVIF/WebP，并保留必要的JPEG/PNG回退。
- 首页照片按已确认要求裁为方图；使用焦点元数据控制响应式裁切，不能每个尺寸手工猜测不同主体。
- 卡片列表固定统一比例；详情页系统图、服务蓝图等允许使用原比例并支持放大查看。
- 首屏关键图设置明确尺寸，避免布局偏移；下方图片懒加载。
- 不对文字密集的系统图过度压缩；必要时提供“查看原图”或PDF来源入口。
- 装饰图片用空alt；内容图片写明它证明什么，避免重复标题。

### 8.3 占位图

- 由统一 `PlaceholderMedia` 生成，不为每处手工制作不同假图。
- 必须显示“素材待补”与计划内容，并保留目标比例。
- 占位状态进入数据字段和测试断言，方便后续统计与替换。
- 正式发布前可允许部分非关键兴趣占位，但不能在核心项目证据位留下含混占位。

### 8.4 视频与外链

- 默认展示封面、标题、来源和“播放/打开视频”按钮，不自动加载播放器。
- 用户主动点击后才加载嵌入；可用时采用隐私增强域名并保留“在YouTube打开”。
- 嵌入失败、拒绝Cookie或网络受限时，仍显示普通来源链接。
- 不下载或重新托管未授权的视频。
- 外链新窗口打开时在可见文案或辅助文本中说明；同时使用安全的 `rel` 属性。

### 8.5 PDF与本地HTML

- 简历PDF放入公开下载目录，使用稳定、可读的下载文件名；链接同时支持浏览与下载。
- 项目源报告默认不全部公开，只有内容方案明确需要的文件才进入部署包。
- OURoute本地HTML不能直接以现状发布：其中包含第三方远程图片和未知部署依赖。R0只使用已整理的页面图；如未来公开HTML，需单独做版权、安全与离线资源审查。

### 8.6 字体

- 优先系统字体回退或经过授权的开源字体。
- 只自托管实际使用的字重和字符子集，避免为装饰字体加载完整大文件。
- 字体加载失败不能改变信息层级；用合适回退字体并控制布局偏移。

## 9. 动效技术方案

### 9.1 分层实现

| 层级 | 技术 | 示例 |
|---|---|---|
| 基础反馈 | CSS transition | 按钮、链接、Tab指示、focus、图片淡入 |
| 进入视口 | IntersectionObserver + CSS类 | 区块轻微显现；无脚本时默认可见 |
| 状态切换 | React局部状态或原生DOM | 筛选、移动菜单、复制反馈 |
| 拖拽/惯性 | Pointer Events + `requestAnimationFrame` | 精选轮播、图库；按钮和键盘是并行入口 |
| 高级路径/渐变 | SVG/Canvas按需增强 | R0后才评估；不可成为核心内容依赖 |

### 9.2 组件实现边界

#### 精选项目轮播

- 只在 Home 或 AI Projects 选择一个位置实现，不能重复。
- 静态基线是项目卡列表；增强后支持拖拽、方向键和前后按钮。
- 活跃索引、拖拽中、速度、归位中为内部状态；标题和CTA不随3D变换倾斜。
- 背景渐变可根据预设项目色组切换，不从跨域图片实时取色，避免Canvas污染和不可控结果。
- 页面隐藏、组件离开视口或减少动态开启时停止动画循环。

#### Stack项目卡

- 使用CSS伪元素或两层装饰卡，不加载真实重复图片。
- `hover` 与 `focus-within` 共用展开状态；触屏保持静态层叠。
- 主链接的点击区域、焦点环和文本不参与旋转。

#### Elastic图库

- R0延后；首版采用静态主图、缩略图和上一/下一按钮。
- 若后续启用拖拽，用卡片宽度的相对阈值，不使用固定200/450px。
- 拖拽捕获失败、取消或窗口失焦时必须安全复位。

#### 区块显现与品牌路径

- 无JavaScript默认内容可见，增强脚本加载后才标记可动画状态，防止水合失败出现空白。
- 路径响应只操作装饰SVG或Canvas，设置 `pointer-events: none`，不拦截页面操作。
- 不实现静态参考图没有证据支持的自动星星闪烁或草木摆动。

### 9.3 减少动态

开启 `prefers-reduced-motion: reduce` 时：

- 禁用3D旋转、惯性、视差、水波、弹性过冲和持续动画循环。
- 所有内容初始可见；页面和筛选结果直接切换或使用不超过150ms的透明度变化。
- 轮播退化为平面列表/按钮切换，Stack保留静态错位，图库使用缩略图。
- 视频不自动播放；不存在自动轮播。
- 测试中必须真实模拟该媒体特性，不能只检查CSS文件包含相应字符串。

## 10. 响应式方案

### 10.1 原则

- 以内容断点而非设备名称决定布局；以下宽度是初始实现基线，R0以真实内容校正。
- 移动端不是桌面缩小版：减少装饰、取消依赖hover的表达、缩短横向位移、保持CTA可见。
- 所有组件在320px内容宽度下不产生非预期横向滚动。

### 10.2 初始断点

| 范围 | 网格与边距 | 主要变化 |
|---|---|---|
| `< 480px` | 4列，20px边距 | 单列卡片、移动菜单、按钮可换行或通栏、装饰最少 |
| `480–767px` | 4列，24px边距 | 部分双列标签/指标，项目仍以单列阅读为主 |
| `768–1023px` | 8列，32px边距 | 双列项目卡、时间线增强、导航视实际宽度决定形态 |
| `1024–1439px` | 12列，48px边距 | 桌面导航、2–3列项目网格、首屏双栏 |
| `≥ 1440px` | 12列，最大1280px居中 | 增加外部留白，不无限放大文字和卡片 |

### 10.3 关键组件响应

| 组件 | 桌面 | 平板 | 移动 |
|---|---|---|---|
| Header | 六Tab横排、粘性 | 视内容决定横排或菜单 | 菜单按钮 + 垂直链接；当前Tab可见 |
| Hero | 文案与方形照片双栏 | 比例收紧 | 文案在前、照片在后；主CTA优先 |
| 经历时间线 | 轴线 + 内容卡 | 轴线缩窄 | 单列，时间作为卡片上方元信息 |
| 项目网格 | 2–3列 | 2列 | 1列 |
| 筛选器 | 横排可换行 | 横向换行 | 横向滚动或下拉；必须有可见标签和结果数量 |
| 项目详情 | 文图交替，窄正文列 | 保持文图层次 | 单列；宽图可在容器内缩放/打开原图 |
| 指标列表 | 3–4列 | 2列 | 1–2列，长单位不截断 |
| 轮播 | 轻3D增强 | 低角度或平面 | 平面横滑 + 按钮 |
| Stack卡 | hover/focus展开 | 静态或focus | 静态层叠，不等待hover |

### 10.4 固定验收视口

- 桌面：1440 × 900。
- 平板：768 × 1024。
- 移动：390 × 844。
- 额外边界：320px窄屏与200%页面缩放。

以上三个固定视口沿用 `RECORD.md`，用于R0和R1–R8每轮截图对比。

## 11. 可访问性方案

### 11.1 目标

- 以WCAG 2.2 AA为设计和测试目标。
- 自动扫描只负责发现部分问题；必须配合键盘、屏幕阅读顺序、缩放和减少动态人工检查。

### 11.2 语义结构

- 每页一个清晰H1，标题层级不跳跃。
- 使用 `header`、`nav`、`main`、`section`、`article`、`footer` 等语义元素。
- 一级Tab实际上是网站导航链接，不错误使用ARIA tab组件；只有同页互斥面板才使用tab语义。
- 经历展开优先使用原生 `details/summary` 或等价可访问披露组件。
- 筛选器使用可识别的按钮组/表单控件，公开选中状态和结果数量。

### 11.3 键盘与焦点

- 所有功能仅键盘可完成；顺序与视觉顺序一致。
- 提供“跳到主要内容”链接。
- `focus-visible` 使用P3规定的星黄外环，不被 `overflow` 裁掉。
- 移动菜单打开时管理焦点范围或保证背景不可误操作；Escape关闭并返回触发按钮。
- 项目详情返回列表后尽量恢复触发卡片或合理位置，但不造成意外焦点跳转。
- 轮播隐藏项移出Tab顺序；按钮提供当前项和总数。

### 11.4 图片、视频与外链

- 信息图片提供描述用途的alt；复杂图在邻近正文提供解释，不能把所有文字塞进alt。
- 纯装饰星点、植物和路径使用空alt或从辅助技术树中隐藏。
- 视频提供标题、来源和外部打开方式；有语音内容时，正式发布前评估字幕或文字摘要。
- 新窗口外链明确告知，图标不能是唯一说明。

### 11.5 颜色、缩放与触控

- 普通文字至少4.5:1，大文字至少3:1；选中、错误和链接不只依赖颜色。
- 支持200%缩放和文本放大，不遮挡、截断或丢失功能。
- 触控目标建议至少44 × 44 CSS px，紧邻目标留足间距。
- 星黄和荧光黄绿上使用墨黑蓝文字，不放小号白字。

### 11.6 状态反馈

- 复制邮箱成功/失败使用可见文字和适度 `aria-live`，状态保持至少2秒。
- 外链失效不显示“可用”徽标；构建前链接检查与界面状态分开处理。
- 筛选空结果说明当前条件并提供“清除筛选”。
- 媒体失败显示替代说明与来源链接，不留下空白框。

## 12. 性能与可靠性预算

### 12.1 初始预算

| 指标 | R0目标 |
|---|---|
| 首屏JavaScript | 只包含导航必要逻辑；复杂岛按可见性加载 |
| 单个交互岛 | 独立加载，不因下方轮播阻塞Header |
| LCP | 实验室与真实数据目标均对齐“良好”阈值，首屏图重点优化 |
| CLS | 目标≤0.1；图片、字体和占位必须预留尺寸 |
| INP | 目标≤200ms；拖拽和筛选不执行重型同步任务 |
| 图片 | 按显示尺寸生成，不向移动端发送桌面原图 |

这些阈值是工程目标，不得在未测试时写成已达成结果。

### 12.2 运行可靠性

- 无JavaScript时：路由、正文、项目链接、邮箱和简历仍可访问；筛选展示全部项目。
- 交互岛水合失败时：卡片和静态媒体仍存在。
- 外部视频或网站失败时：不影响当前页面渲染。
- 不在客户端读取D盘路径；所有生产素材必须进入项目或公开URL。
- 404页提供六个Tab和返回首页入口。

### 13.3 核心E2E场景

1. 首页加载后可识别姓名、定位、两个主CTA和简历入口。
2. 六个导航链接访问正确URL，刷新后保持页面，父级Tab激活正确。
3. 首页代表证据卡进入相应经历锚点或项目详情。
4. 经历展开/收起不丢失焦点；目标锚点可定位并展开。
5. AI筛选可组合预设分类、更新URL、刷新保持、无效值回退。
6. Portfolio筛选、项目详情、返回列表和筛选恢复正确。
7. Smart Clothing Advisor显示GitHub和视频；OURoute显示团队属性和“组长”职责，不暗示独立完成。
8. 邮箱可复制；模拟剪贴板失败时仍能手动选取邮箱。
9. 简历链接返回正确PDF且文件名可读。
10. 外链有可访问名称、新窗口说明和安全属性。
11. 减少动态模式关闭3D、惯性、显现位移和弹性，核心内容仍完整。
12. 禁用JavaScript时可浏览主要页面、详情、邮箱和下载简历。

- 移动菜单打开状态；
- 减少动态模式下的关键页面。

截图只用于发现变化，不能替代内容和交互断言。

### 13.5 无障碍人工清单

- 只用Tab、Shift+Tab、Enter、Space、方向键和Escape完成核心流程。
- 检查焦点是否始终可见、顺序合理且未落入隐藏轮播项。
- 使用屏幕阅读器抽查页面标题、导航、标题层级、项目卡、筛选和复制反馈。
- 200%缩放及浏览器文字放大后检查导航、卡片、按钮和详情图。
- 开启系统减少动态后实际操作全部交互。
- 检查颜色之外是否仍能识别链接、选中、错误和成功状态。

## 14. 内容与链接质量控制

- 构建前运行内容模式校验：slug唯一、必填字段、分类枚举、媒体ID和项目引用存在。
- 检查本地资源引用、PDF、图片尺寸和无效内部链接。
- 外部链接检查结果只用于发布审查；网络暂时失败不自动删除内容。
- 链接记录最近核验日期和结果，不在页面宣称未经确认的“在线可用”。
- 所有结果数字与原始文档对照，禁止自动“优化”措辞造成因果扩大。
- P2允许公开的视频仍要在发布前复核实际目标和嵌入许可。

## 15. 安全与隐私

- 无后端、无数据库、无账户和无联系表单，减少攻击面与隐私收集。
- 邮箱和电话属于用户明确同意公开的信息；集中配置，便于未来统一撤下。
- 外部嵌入按点击加载，减少第三方追踪；可始终选择只提供普通链接。
- 不提交访问令牌、私有文件路径或未授权源素材。
- 若未来增加分析工具，必须优先无Cookie/低数据方案，并在上线前补隐私说明；P4不默认加入分析。
- 设置基本安全响应头和内容安全策略的部署计划；嵌入来源加入白名单而非开放任意域名。

## 16. SEO与分享

- 每个Tab和项目详情有独立标题、描述、canonical URL和社交分享图。
- 首页结构化信息只使用真实姓名、教育、项目与联系方式，不添加未确认职位或所在地。
- 项目页描述来自同一内容数据，不单独手写一套SEO夸张文案。
- 生成站点地图、`robots.txt` 和404页；部署域名确定后再写最终canonical。
- 分享图可由真实项目封面与统一品牌框架组合；缺素材时使用明确的品牌图，不生成假项目界面。
